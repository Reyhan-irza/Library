# VIREON — PHASE 2
# CORE LIBRARY BORROWING WORKFLOW
# SELF-SERVICE + ADMIN-ASSISTED + APPROVAL + INVENTORY + TRANSACTION TRACKING

You are working on the existing VIREON Library web application.

The objective of this phase is to implement and refine the REAL library borrowing workflow for a school environment.

VIREON must support two borrowing methods:

1. SELF-SERVICE BORROWING
   Students access VIREON without logging in, browse available books, submit a borrowing request, and wait for administrator approval.

2. ADMIN-ASSISTED BORROWING
   Students who do not have a phone, do not have internet access, or need assistance can ask a library administrator to enter the borrowing transaction directly through the admin dashboard.

Both methods must use the same underlying library inventory and transaction system.

## 15. INVENTORY INTEGRITY
==================================================

This is critical.

Inventory must be based on real database state.

Never hardcode available copies.

Prevent:

available copies < 0

When a borrowing is approved or created:

- Inventory must be updated safely.
- The system must re-check availability at the moment of approval/creation.
- Do not trust only the number previously shown in the public UI.

Consider concurrent requests.

Example:

Book has:

10 total
2 available

Student A requests 2.

Before approval, Student B also requests 2.

The system must prevent both approvals from successfully consuming the same 2 copies.

Use an appropriate transactional/database-safe approach supported by Supabase/Postgres.

Do not solve concurrency only in client-side React state.
